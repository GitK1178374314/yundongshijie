## 功能

- **登录**：支持人机验证（GT4 滑块）自动通过，本地完成、不依赖外部服务
- **一键跑步**：策略 → 打卡点 → 轨迹 → 提交 → OBS 上传 → 详情回读校验，全链一条龙
- **定时任务**：多账号无人值守（详见下文）
- **设备身份**：DeviceId / 安装时间 / MAC 持久化，同一账号长期稳定
- **AI 运动**：任务 / 自由练习双模式，支持批量补签
- **数据与自查**：学期完成度、违规通报名单自查、个人/班级/院系排行榜
- **自动更新**：桌面端检查 / 下载 / 自替换并重启
- **托盘与自启**：关闭最小化到托盘，配合定时任务 7×24 无人值守

## 定时任务怎么用

1. 先到「跑步功能」页把参数调好（类型 / 距离 / 配速 / 路线 / 跑区）
2. 进「定时任务」页，填任务名、账号密码、时间区间、首次尝试时间、起止日期
3. 保存后每个账号就是一个独立任务，各自带自己的设备指纹与定位锚点

**排程规则（v0.4.0）**

- 每天在「首次尝试时间」之后随机等 0~6 分钟提交（每天重抽，不是每天同一秒）
- 同一批任务聚在同一时刻附近，实际先后由**串行排队**决定（一次提交约 7 秒）
- 计分跑不会排到 22:00 之后；同一任务当天重复提交至少间隔 30 分钟
- 程序启动时与点「重排今天的时间」时，都会按上述规则硬重算一遍

**执行机制**

- 到点若当前登录账号不是该任务的账号 → 自动登出 → 用任务凭据登录 → 提交 → 按设置自动登出
- 登录失败分级退避重试；网络异常单独退避；执行明细保留最近 100 条（含 rrid / OBS / 校验结果 / 过程日志）

## CLI 用法

```text
美信乐跑 login --user <手机号> --pass <密码> --remember    # 登录并保存凭据
美信乐跑 run                                                # 一键跑步（可加 --type credit|free --dist km --pace 秒/km）
美信乐跑 ai --sport 2 --score 26000                         # AI 运动
美信乐跑 rank main --type 1 --sort 1                        # 排行榜
美信乐跑 logout                                             # 登出并清理本地会话
美信乐跑 help                                               # 全部命令
```

## 数据文件（exe 同目录，绿色便携）

| 文件 | 内容 |
|---|---|
| `config.json` | 全局设置（主题、设备方案、定时任务开关、计划关机时刻…） |
| `identity.json` | 全局设备指纹与定位锚点 |
| `scheduled_tasks.json` | 全部定时任务 + 执行明细（账号密码为本地混淆存储，**不是强加密**） |
| `task_heartbeat.json` | 心跳：进程存活、下次执行时刻 |
| `points_cache.json` / `fence_cache.json` | 点位与围栏缓存（减少触发接口限流） |
| `任务记录.log` | 运行诊断日志 |

升级只需替换 exe；**不要删 `identity.json`**（等于换了新设备，容易触发风控提示）。

## 常见问题

- **提示未登录 / 401**：先 `login --remember`（GUI 勾「记住登录状态」等价），会话失效会自动重登
- **10121「已在其他设备登录」**：同一账号在别处（手机官方 App / 另一个程序实例）还有活跃会话，
  先把那边退出，等一小时后自动恢复。**设备身份是持久化的，不要频繁删 `identity.json`**
- **10603 点位限流**：点位接口 5 分钟限 3 次，程序内置 300 秒缓存，正常使用不会触发
- **10600「当前学校尚未设置点位」/ 围栏为空**：该学校（校区）没有配置跑区或打卡点，
  这是服务端配置问题；此类账号只能用「经典模式」跑，或换账号
- **11016「不在有效跑步时间内」**：该校计分跑有开放时段（各校不同，例如 08:01–22:30），
  把定时任务的时间区间放进该时段内即可
- **人机验证失败**：自动重试多轮，仍失败多为网络波动，稍后再试
- **杀软误报**：未签名编译产物可能被误报，自行判断后加白名单
